Google Search Operators Master Reference

Search operators permit fine-grained filtering of Google's public web index. They are invaluable for discovering accidentally exposed endpoints and reviewing organizational attack surfaces.

Operator Syntax Pattern Targeted Discovery Purpose
site: site:domain.com Restricts search results strictly to a domain or subdomain.
filetype: / ext: filetype:pdf OR ext:sql Filters by indexed file extension (PDF, SQL, ENV, BAK, CSV).
inurl: inurl:login OR inurl:admin Matches keywords positioned anywhere in the URL request path.
intitle: intitle:"index of /" Matches exact phrases inside HTML <title> tags.
intext: intext:"confidential" Finds specific strings anywhere inside indexed page body text.
related: related:domain.com Discovers domains categorized by Google as structurally related.
-exclusion site:*.domain.com -www Excludes specific hosts to reveal hidden dev and api subdomains.
quotes "" "internal use only" Forces strict literal token matching without fuzzy stemming.
OR / | inurl:auth OR inurl:oauth Performs logical disjunction between multiple dork predicates.
wildcard * site:*.api.target.com Acts as an arbitrary token or hostname wildcard.

Webmaster Defense & Dork Remediation

How website administrators and infrastructure engineers can prevent search engine dorking from exposing sensitive assets:

1. Disable Server Directory Indexing

Prevent Apache or Nginx from listing folder trees when index.html is missing:
# Apache (.htaccess): Options -Indexes
# Nginx: autoindex off;

2. Restrict Sensitive Extensions at the Proxy Level

Block public HTTP access to configuration, database dumps, and version control files:
location ~* \.(env|cfg|ini|bak|sql|log|yml)$ { deny all; }
location ~ /\.git { deny all; }

3. Implement Proper Robots Directives & Headers

Note that robots.txt tells cooperative crawlers what not to index, but does not secure assets. Use the HTTP header X-Robots-Tag: noindex, nofollow on private portals and administrative gateways.

Deceptive URL Anatomy & Attack Vectors

Userinfo '@' Symbol Spoofing (RFC 3986)

In standard URL syntax, https://trusted-bank.com@attacker-site.com passes trusted-bank.com as the HTTP basic authentication username. The browser ignores the text before @ and connects directly to attacker-site.com.

Punycode & IDN Homograph Attacks (xn--)

Internationalized Domain Names allow non-ASCII characters. Attackers substitute Latin letters with visually identical Cyrillic glyphs (e.g., Cyrillic а for Latin a). The browser encodes this as xn--pple-43d.com, tricking users into believing they are visiting apple.com.

Subdomain Stacking & Brand Spoofing

Attackers register cheap domains (e.g., verification-update.xyz) and prepend legitimate brands as subdomains (e.g., paypal.com.verification-update.xyz). On mobile viewports, the actual domain is often pushed out of sight.

Open Redirects & SSL Protocol Downgrades

Phishing campaigns leverage open redirect parameters (/redirect?url=...) on legitimate domains to pass email security filters. Additionally, protocol downgrades shift traffic from HTTPS to unencrypted HTTP to intercept credentials.

Security Analyst Investigation Playbook

A step-by-step methodology for security operations center (SOC) analysts, threat researchers, and incident responders examining suspicious links and domain footprints:

PHASE 1

Target Authorization & Scoping

Ensure explicit written authorization from the domain owner. Define rules of engagement and verify that passive analysis will not conflict with enterprise change-freeze policies.

PHASE 2

OSINT Surface Discovery

Deploy categorized Google dorks across documents, login portals, and exposed backups. Search Pastebin and GitHub for developer credential leaks and API keys referencing the domain.

PHASE 3

Structural & Network Dissection

Parse RFC-3986 URL parts, query parameters, and port numbers. Resolve DNS records (IPv4/IPv6, PTR) and inspect SSL certificate validity, issuer trust, and Subject Alternative Names (SANs).

PHASE 4

Redirect Chain & Threat Scoring

Trace up to 10 redirect hops without downloading payloads. Check for cross-domain hops, HTTPS downgrades, and evaluate heuristic flags (homoglyphs, brand spoofing, TLD reputation).

PHASE 5

Reporting & Remediation

Export forensic reports in TXT, CSV, or JSON. If phishing is identified, submit abuse reports to registrars, publish Indicators of Compromise (IoCs), and configure firewall perimeter blocks.

Ethical Rules of Engagement

Authorized cybersecurity research requires strict adherence to ethical standards:

  • Passive Analysis Only: Do not exploit discovered vulnerabilities or probe unauthorized networks.
  • Respect Data Privacy: If sensitive personnel records or credentials are found in public indexes, report them responsibly.
  • No Denial of Service: Never issue high-volume automated requests that degrade target availability.
  • Coordinated Vulnerability Disclosure: Provide domain owners a reasonable timeframe to remediate leaks before public discussion.

Legal Frameworks & Compliance

Key legislation governing cybersecurity assessments and information gathering:

  • CFAA (United States): Prohibits accessing protected computers without authorization. Safe harbor requires documented consent.
  • Computer Misuse Act 1990 (United Kingdom): Section 1 & 3 prohibit unauthorized access or acts impairing computer operation.
  • GDPR / EU Cyber Resilience Act: Processing discovered personal data requires lawful basis and data protection impact assessments.
